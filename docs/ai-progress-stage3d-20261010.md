## 1. Реализовано

- История использует **существующие** `fgi_ai_workouts` и реальные snapshot/подходы из 3C. Программа и её плановые нагрузки не становятся фактическими результатами.
- Управляемые ответы до вызова модели: «Когда я тренировался последний раз?», «Сколько тренировок я сделал за неделю?», «Покажи последние тренировки», «Какие тренировки я уже выполнил?», «Какой вес я жал в прошлый раз?» / «…жал лёжа…».
- Учитываются только строки со статусом `completed` и известным `completed_at`. Остановленные занятия остаются доступны отдельным списком. При нескольких подходящих упражнениях требуется название; отсутствующие вес/повторения явно обозначаются как неизвестные.
- Подсчёт за неделю охватывает последние **7 календарных дней, включая сегодня**, в часовом поясе клиента. Ответ указывает точный интервал и пояс. Подсчёт выполняется по всей базе, независимо от размера отображаемого списка. Поиск результата упражнения также охватывает всю историю.
- «Сегодня я вешу 84 кг» и «Запиши мой вес 83,5 кг» сохраняют отдельную строку. Поддержаны ISO-дата, `01.10.2026`, «1 октября 2026», сегодня/вчера/позавчера и явный комментарий. Без года используется текущий год, который явно показывается в ответе. Неопределённая прошлая дата требует уточнения; примеры, условные фразы, несколько весов и неизвестные единицы не записываются.
- «Сколько я весил раньше?» и «Покажи изменение моего веса» показывают реальные измерения и простую разницу первого/последнего. История без записей получает честное пояснение; одиночное значение профиля без даты не превращается в выдуманную историю.
- «Мой прогресс» содержит последнее измерение, последнюю выполненную тренировку, форму, списки измерений и результатов. Каждый новый вес сохраняется отдельно, включая второй вес в тот же день. Сохранены прежние талия, сон, энергия, приватные фото, экспорт и удаление. Новые графики, автоматическая аналитика и адаптация программы не добавлены.
- После обновления/смены аккаунта данные загружаются из Supabase. Поля новой записи не заполняются предыдущим весом автоматически.

## 3. Таблицы и пример данных

**Новых таблиц нет.** Миграция создана настоящим `supabase@2.120.0 migration new ai_progress_history`.

В `fgi_ai_progress` удаляется ограничение `UNIQUE(user_id, recorded_on)`, которое прежде перезаписывало запись за тот же день. Добавляются:

- `recorded_at timestamptz`: время добавления на сервере. Это **время записи**, не выдуманное время измерения. Для прежних строк остаётся `NULL`.
- `timezone text`: пояс, используемый для текущей даты и запрета будущих дат.
- `source text`: `legacy`, `form`, `chat` или `profile`.

Прежние `id`, `user_id`, `recorded_on`, `weight_kg`, `waist_cm`, `sleep_hours`, `energy`, `notes`, `photo_path` сохранены. Owner/date индекс обеспечивает порядок; отдельный частичный индекс поддерживает выполненные тренировки. Исправлен фактически проверенный прежний CHECK фото, отклонявший нормальный owner JPEG path из-за двойного escape точки; ограничение owner-пути сохранено.

Пример структуры (иллюстрация, не данные реального пользователя):

```json
[
  {"id":"measurement-1","user_id":"owner","recorded_on":"2026-10-01","weight_kg":85,"notes":"Утро","source":"form"},
  {"id":"measurement-2","user_id":"owner","recorded_on":"2026-10-05","weight_kg":84,"notes":"","source":"form"},
  {"id":"measurement-3","user_id":"owner","recorded_on":"2026-10-09","weight_kg":83.5,"notes":"После пробуждения","source":"chat"},
  {"id":"measurement-4","user_id":"owner","recorded_on":"2026-10-09","weight_kg":83.4,"notes":"Повторное измерение","source":"form"}
]
```

Настоящие `id`/`user_id` являются UUID. Вес допускает 20–300 кг с точностью до 0,01 кг; дата 2000-01-01 — сегодняшний день в указанном поясе. Талия остаётся в см. Последним считается максимальная дата измерения, затем время добавления; старые строки без времени сохраняются без догадки.

## 4. Сохранение, согласованность и безопасность

Форма сохраняет строку с новым UUID. Повтор доставки использует прежний UUID и INSERT с игнорированием того же ID, затем проверяет собственную строку. Неопределённая доставка сохраняет данные повтора в sessionStorage и предлагает проверку/повтор; новая вкладка загружает историю из базы. Каждое самостоятельное новое измерение получает новый ID.

Чат использует существующий delivery nonce как ID измерения и существующую транзакцию `fgi_ai_complete`. Строка, сообщение и ответ фиксируются вместе. В retry cache не сохраняются внутренний `progress_record` и технический timezone. Ошибка сохранения не возвращает утверждения «сохранено».

Триггеры блокируют профиль владельца и обновляют его вес в той же транзакции INSERT. Позднее добавленный старый вес не заменяет более свежий. Явное изменение веса через прежний профиль и смешанный спортивный intake также добавляет историю. Очистка поля не уничтожает известное последнее измерение. Существующие датированные строки сверяются с профилем при миграции; для старого профиля без измерений даты не выдумываются. Система питания и версии программы сохранены.

Измерения не перезаписываются через UPDATE; прежнее удаление фото и удаление личных AI-данных остаются доступными. Owner-only RLS `USING`/`WITH CHECK` сохранена на обеих таблицах. Backend получает ID через Supabase Auth `getUser` HTTP endpoint; переданный клиентом `user_id` игнорируется. `fgi_ai_history` и внутренние helpers используют `SECURITY INVOKER`, пустой search_path, явно фильтруют владельца и недоступны browser/anon. Клиентский профиль не даёт прав другому аккаунту.

История через чат сохраняет прежние модульные права и лимиты запросов AI. Управляемые команды не вызывают provider и не расходуют его платные токены. Форма дневника остаётся доступной по прежним правам без платного AI.

## 6. Ограничения и оставшийся выпуск

- Базовые русские команды и известные форматы даты; сложные временные описания, исправление/удаление отдельного измерения и массовый импорт не добавлены.
- Чат показывает последние 20 измерений и 10 выполненных тренировок. Сравнение первого/последнего и недельный счёт используют всю сохранённую историю. Интерфейс раскрывает по 30 строк до действующего API предела около 1000; база сохраняет все строки. Прежний экспорт не переработан.
- Смешанный intake продолжает существующий validated memory flow. Фактический вес создаёт датированную запись; сложные прошлые даты лучше отправлять отдельной командой.
- По упражнению показываются записанные подходы. Неизвестная нагрузка/повторения не подменяются программой. Несколько названий требуют уточнения.
- Production 3B/3C/3D migration, Edge Function и frontend ещё не установлены. DESKTOP-EJAAHVB Offline блокирует обязательную Windows проверку и выпуск.

Для выпуска: чистый отдельный Windows checkout, чтение AGENTS.md/этого отчёта, `npm.cmd run check`, `npm.cmd run deploy:dry`; reviewed main со всей зависимой цепочкой 3B→3C→3D, последовательные migration 20261009141146 / 20261010083455 / 20261010101602, полный Edge handler (index и девять импортированных модулей), повторная Auth/RLS acceptance и advisors.
